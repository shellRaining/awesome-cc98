## 已建立的项目知识

- `exhibits/*/exhibit.yaml` 是展品事实的单一来源，目前有 24 条记录。
- `collections/readme.yaml` 和 `collections/gallery.yaml` 负责不同出口的选择、分组与顺序。
- YAML 是人工编辑的规范格式；通过 Schema 与跨文件校验后生成 README、`generated/catalog.json` 和 `generated/assets.json`。
- `ASSETS.yml` 区分远程候选与批准入库的共享素材；展品专属素材归对应展品记录管理。
- 网络公开不等于允许再分发。来源、作者、权利依据、署名、隐私复核和哈希必须跟随本地素材。
- push 和 PR 会在 Node.js 22、pnpm 11 下运行完整检查；校验器会拒绝缺失、未登记或越出 `assets/` 目录的素材文件。
- 二期游戏的房间与摆放数据位于 `scenes/*.yaml`，通过展品 ID 引用目录，不复制展品事实；运行时只消费校验后生成的 JSON。

完整决策和目录职责见 [项目决策](project-decisions.md)。

2026-07-29 的入库快照：

- `assets/authors/` 下有 29 个文件，总计 1,358,509 字节，其中 GitHub 头像 20 份、CC98 头像 9 份。
- 29 个文件均在 `ASSETS.yml.assets` 中登记，包含稳定 ID、关联展品、公开账号、原始 URL、获取日期、署名、权利依据、隐私状态和 SHA-256。
- 本地文件与 29 个远端头像直链的 SHA-256 全部一致；媒体类型与扩展名一致，没有零字节文件，也没有发现 EXIF、XMP、IPTC 或 GPS 元数据。
- 3 个以 `-default.png` 结尾的文件是同一份 CC98 默认头像。为保留账号级来源并允许未来独立更新，当前为三个账号分别建立素材记录和文件副本；清单明确标注其为默认头像，不把它归因于账号本人创作。
- `generated/assets.json` 包含 33 个 `publish: true` 的本地素材：29 个作者头像与 4 个博物馆生成素材；不包含 `ASSETS.yml.candidates`。
- README 为每个展品显示作者署名，并按策展顺序生成 21 个作者身份的创作者墙；运行时目录为每位作者生成可追溯到素材清单的头像 key。
- `pnpm check`、全量链接检查和 `git diff --check` 已通过；链接检查中的临时网络限制只产生警告，没有确认失效的链接。

## M3 可玩基线快照

2026-07-30 的当前实现包括：

- 入口大厅、当代客户端馆、工具实验室、官方参考馆、历史档案馆和隐藏记忆密库共 6 个空间，24 件展品在场景中各出现一次。

- A、C、AC 三套视觉稿与记忆碎片均已在 `ASSETS.yml` 登记为 `publish: true` 的 CC0-1.0 生成素材；源图、提示词和处理过程保留在 `output/imagegen/`。
