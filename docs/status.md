## 已建立的项目知识

- `exhibits/*/exhibit.yaml` 是展品事实的单一来源，目前有 24 条记录。
- `collections/readme.yaml` 和 `collections/gallery.yaml` 负责不同出口的选择、分组与顺序。
- YAML 是人工编辑的规范格式；通过 Schema 与跨文件校验后生成 README 和 `generated/catalog.json`。
- `ASSETS.yml` 区分远程候选与批准入库的共享素材；展品专属素材归对应展品记录管理。
- 网络公开不等于允许再分发。来源、作者、权利依据、署名、隐私复核和哈希必须跟随本地素材。
- 二期游戏的数据应放在未来的 `scenes/*.yaml` 中，通过展品 ID 引用目录，不复制展品事实。

完整决策和目录职责见 [项目决策](project-decisions.md)。

## 当前提交判断

目录与文档部分适合独立提交；正在下载的资产批次目前不适合直接提交。检查时工作区中的头像均为未跟踪文件，而 `ASSETS.yml.assets` 仍为空，因此它们尚未满足仓库自己的本地素材规则。

资产批次在同时满足以下条件后再提交：

- 下载任务已经结束，文件清单不会继续变化。
- 每个文件都在 `ASSETS.yml` 或对应展品记录中登记，不存在孤立文件。
- 登记包含稳定 ID、文件路径、媒体类型、替代文本、原始来源、获取日期和 SHA-256。
- 权利状态、作者、署名与使用确认有可追溯记录。
- 人工检查图片内容、默认头像、重复文件、异常尺寸和隐私信息。
- `pnpm check` 通过，且 `git diff --check` 无错误。

建议拆成两个提交边界：

1. 路线图、状态和项目决策文档。
2. 完整登记并审核后的作者头像与素材元数据。

这样可以避免把仍在变化或尚未登记的二进制素材混入知识文档提交，也便于单独复核资产授权和体积。
