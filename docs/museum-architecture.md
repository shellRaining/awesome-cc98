# 2D 博物馆实现架构

本文记录 M3 的实现边界。展品事实仍由 `exhibits/*/exhibit.yaml` 维护，场景、游戏状态和表现层不得复制或改写这些事实。

## 运行时分层

```text
exhibits/ + collections/ + ASSETS.yml + scenes/
                    ↓ 校验与生成
generated/catalog.json + assets.json + scenes.json
                    ↓ prepare-museum
apps/museum/public/data + 已批准素材副本
                    ↓
Phaser 世界层 + DOM 信息与无障碍层
```

- Phaser 负责房间、角色、镜头、碰撞、传送门、展品距离检测、收藏品和环境效果。
- DOM 负责加载状态、设置、展品详情、作者与素材署名、外部链接和屏幕阅读器文本。
- 运行时只读取生成后的 JSON；YAML、素材候选和未发布文件不会进入网页包。
- 场景只引用 `exhibit_id` 与 `asset_id`，作品名称、作者、许可证和链接始终来自目录。

## 项目结构

```text
apps/museum/                 Phaser + Vite + TypeScript 应用
scenes/                      人工维护的房间与摆放数据
schemas/scene.schema.json    场景结构约束
scripts/generate-scenes.mjs  场景校验与 JSON 生成
scripts/prepare-museum.mjs   复制运行时 JSON 与已批准素材
generated/scenes.json        可复现的场景产物
```

## 视觉方向

A、C、AC 三套概念图和记忆碎片已经正式入库，分别位于 `assets/museum/concepts/` 和 `assets/museum/memory-shard.webp`。它们在 `ASSETS.yml` 中登记为 `publish: true`、`generated`、CC0-1.0，并通过生成清单进入运行时。源图、提示词与处理过程保留在 `output/imagegen/`。

- 入口大厅采用 A+C：温暖木色、轻快校园细节与中等对比度。
- 当代客户端馆和工具实验室采用 C：明亮、开放、轻松。
- 官方参考馆采用较克制的 A+C。
- 历史档案馆采用 A：更深的木色、安静灯光和怀旧设备。
- 所有房间共用 32 像素逻辑网格、角色比例、家具轮廓和交互高亮，主题差异主要通过色板、灯光和陈列密度表达。

概念图当前作为馆内海报和视觉基准使用，不会直接缩放成地图背景。场景以程序化空间、独立碰撞体和装饰层构成，后续正式美术仍应拆为可复用 tile、家具与角色素材。

## 场景与坐标

- 坐标以 tile 为单位，渲染时乘以场景的 `tile_size`。
- `spawn`、展品、传送门、收藏品和装饰必须位于房间范围内。
- 固定边界和家具碰撞使用矩形，避免从图片像素推断碰撞。
- 传送门必须指向存在的场景和出生点；从入口出发应能到达全部展厅。
- 同一策展集合中的展品在 M3 主场景里应各出现一次；临时重复展示需要显式标记用途。

## 展品交互

所有展品支持一套共同流程：靠近、显示提示、打开详情、查看作者与署名、访问外部来源。重点作品可以在共同流程之后进入专属互动。

当前 16 个专属互动展位覆盖 7 类模板：

1. 设备展柜：旋转或切换屏幕状态。
2. 界面操作：切换模拟页面或展示状态，观察客户端的信息组织方式。
3. 界面对比：在不同版本、平台或视觉方案之间切换。
4. 终端演示：输入少量安全的预设命令查看模拟输出。
5. 代码观察台：展示经过整理的公开技术信息，不直接执行第三方代码。
6. 时间轴：沿年份查看客户端与平台迁移。
7. 特征筛选器：按公开特征筛选并比较相关信息。

这些模板依据目录中的公开事实构造本地模拟，不嵌入原客户端，也不执行第三方代码。

## 状态与存档

- 存档只保存在浏览器 `localStorage`，不要求 CC98 登录，也不上传访客身份。
- 当前存档版本为 v2，核心字段包括 `visitedScenes`、`discoveredExhibits`、`favorites`、`collected`、`flags` 和 `settings`。
- 设置包含 `muted`、`volume`、`reducedMotion`、`highContrast` 和 `performanceMode`，默认音量为 0.65。
- v1 存档会迁移到 v2；损坏、未知版本或不可用的浏览器存储会安全回退，不阻断游览。
- 数组和标记会稳定排序并去重，使相同状态得到稳定的序列化结果。兼容字段 `collected` 与 `flags` 保留给碎片、彩蛋和互动进度。
- 外部链接必须由用户明确点击，游戏不会代替用户登录或调用 CC98 私有接口。

## 可访问性与性能

- 键盘、触屏和基础手柄共享同一动作映射。
- 信息面板保持正常 DOM 阅读顺序，打开时锁定游戏输入并管理焦点，关闭后焦点返回游戏入口。
- 支持减少动态效果、静音和高对比交互提示。
- 房间按需加载；限制设备像素比；程序化背景与纹理图集避免大量独立绘制调用。
- 低性能模式可以关闭装饰动画、光照覆盖层和粒子，不影响展品访问。

## M3 验收边界

- 从入口可到达 5 个常规空间；集齐 5 个记忆碎片后，可以从历史档案馆进入第 6 个空间隐藏记忆密库。全部 24 件展品在场景中各出现一次。
- 每件展品都能打开由目录数据生成的详情和署名。
- 16 件重点作品具备专属互动，共覆盖 7 类模板；其余作品使用完整通用展陈。
- 导览、收藏品、隐藏路线、彩蛋、设置和本地进度形成可完成的游览闭环。
- 所有打包素材均来自生成清单，构建、测试和静态预览可以从全新检出复现。

上述验收边界已经达到，M3 当前状态为已完成可玩基线。真实项目图标、截图、海报和演示素材仍需按 M1A 逐项完成授权、署名与隐私审核，这属于持续策展，不改变运行时只消费批准素材的边界。
