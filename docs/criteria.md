# 收录与状态规则

## 收录范围

主目录收录面向 CC98 的客户端、替代网页、PWA、终端界面、浏览器扩展、编辑器扩展和有独立交互设计的用户脚本。官方前端放在“官方参考”分区，未完成或发布渠道有限的项目放在“预览与实验”分区，停止维护的作品进入历史馆。

签到器、爬虫、数据归档、API 封装和通用 UBB 库不进入客户端主目录。将来可以为它们增加单独的工具集合。

项目至少需要满足以下条件：

- 能确认它以 CC98 为目标。
- 有可运行版本、在线地址，或者能够复现的源码。
- 有独特交互设计或明确的平台覆盖。
- 至少有一个公开且可复核的来源。
- 能如实记录维护、分发和许可证状态。

社区规模较小，Star 数不能稳定反映完成度，因此不设置 Star 门槛。

## 生命周期

`stable` 表示已有公开分发，核心浏览和交互能力可以正常使用。`public_beta` 表示可以测试，但作者仍明确提示功能不完整、存在较多问题或分发会到期。`experimental` 用于早期重写、Canary 和课程原型。`legacy` 表示项目已停止维护，或者只能作为历史源码和旧安装包查看。无法从现有证据判断时使用 `unknown`。

维护状态与生命周期分开。仓库近期有提交可以记为 `active`，较长时间没有更新但仍可能可用时记为 `quiet`，作者明确停止或仓库归档时记为 `unmaintained`。没有证据时使用 `unknown`。

## 证据等级

`verified` 表示关键字段能由仓库、Release、商店等一手来源交叉确认。`mixed` 表示一部分事实已确认，功能描述或当前可用性仍来自作者说明。`self_reported` 表示主要依据作者宣传。`unverified` 只用于等待复核的草稿，不应进入公开集合。

每个具体功能还要标记 `author_claim`、`observed` 或 `independently_verified`。维护者没有实际运行客户端时，不把 README 中的功能写成独立验证结果。

## 失效与撤下

链接失效不会自动删除展品。维护者先更新 `availability` 和核验说明，保留项目在客户端历史中的位置。作者要求撤下素材时移除对应文件；事实记录可以缩减为 `tombstone`，保留最少的项目名、来源和撤下说明。
