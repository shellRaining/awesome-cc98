# 素材规则

M0 和 M1 允许展品没有图片。公开图片需要明确的来源和使用依据，不能为了填满画廊复制站内截图或商店素材。

## 可以公开的素材

- 本项目自行创作并明确授权的图片、图标、音效和视频。
- 通过 ImageGen 等工具生成，并由贡献者确认可以公开的原创素材。
- 许可证允许再分发的 CC0、CC-BY、OFL 或其他兼容素材。
- 权利人明确授权 Awesome CC98 使用的截图、图标或演示。
- 使用 mock 数据本地构建并截图，且项目许可证和品牌使用范围允许公开的界面。

仅仅能在网络上下载，不代表素材可以重新发布。应用源码采用 MIT、Apache-2.0 等许可证，也不自动覆盖应用名称、Logo、商标、截图和商店宣传图。

## 禁止公开的内容

- 真实帖子、用户名、头像、私信、IP、访问令牌和登录凭据。
- 带可追溯水印或能识别论坛用户的截图。
- 来源不明的图包、音乐和字体。
- 未经许可重新托管的 APK、IPA、AppX、VSIX 或其他二进制安装包。
- 从官方商店或作者页面复制，但没有再分发依据的宣传图。

## 记录方式

展品专属素材放在 `exhibits/<id>/assets/`，并在该展品的 `assets` 字段中登记。博物馆共用的地板、家具、角色和音效放在根 `assets/`，登记到 [ASSETS.yml](../ASSETS.yml)。

每项记录包含稳定 ID、文件路径、媒体类型、替代文本、来源、获取日期、SHA-256、是否公开以及权利状态。`publish: true` 只接受以下状态：

- `licensed`：许可证允许公开，并填写许可证和署名。
- `permission_granted`：权利人已明确授权，并能找到许可记录。
- `self_created`：由贡献者原创，贡献者同意按指定方式发布。
- `generated`：由生成工具制作，提示词和后续编辑过程可追溯。

`permission_required` 和 `unknown` 素材可以用于内部核验记录，但必须设置 `publish: false`。CI 会检查文件哈希和发布权利。

## 授权记录

公开许可链接可以直接写入记录。私聊或邮件授权只在 [permissions/](permissions/) 中保存脱敏摘要，包括授权对象、范围、日期和维护者确认，不提交私人联系方式或完整聊天记录。
