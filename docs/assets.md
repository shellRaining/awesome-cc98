# 素材规则

公开页面上的图片可以先登记来源，但登记不等于取得再分发许可。Awesome CC98 把素材分成候选记录和本地文件两层，先保存线索，确认权利与隐私后再把文件放进仓库。

## 候选记录

`ASSETS.yml` 的 `candidates` 保存以后可能使用的图标、截图、视频和宣传页。候选只记录 URL 与审核信息，不下载文件，且必须保持 `publish: false`。

每条候选记录包含：

- 对应展品、素材类型和预期用途。
- 原页面、直接资源 URL 和获取日期。
- 创作者、发布者或已知权利人，以及建议采用的署名文字。
- 许可证或授权状态。
- 隐私检查结果，以及是否需要裁切、打码或重新制作。

`creator` 记录素材创作者，`owner` 记录发布账号或已知权利人。`owner` 只用于追溯，不构成法律上的所有权判断。隐私状态分为：`clear` 表示没有发现个人或论坛内容；`public_promotion` 表示作者主动公开的宣传素材；`public_identity` 表示只保留必要的公开作者身份；`needs_redaction` 表示发布前必须处理；`unknown` 表示尚未检查。

没有公开图片的项目也可以登记候选。此时 `asset_url` 和 `media_type` 为 `null`，备注中写明准备向作者索取的素材，不应拆解安装包或复制不稳定的站点预览图来填补空缺。

## 公开帖子和作者信息

作者主动发布的宣传帖、商店页、README 截图、公开用户名和头像可以作为候选来源。记录中需要保留原位置、作者和获取日期。准备正式发布时，还要同时满足素材授权和隐私最小化要求。

- 作者身份、项目署名或品牌水印本来就是宣传内容的一部分时可以保留，不应抹去作者信息。
- 画面中的其他用户名、头像和帖子正文如果只是背景，应裁切、打码，或请作者用模拟数据重新截图。
- 展示真实公开帖子确有策展价值时，应保留帖子原链接和作者署名，只截取说明作品所需的最小范围，并取得截图作者及相关权利人的许可。
- 能追踪登录账号、访问者、设备或会话的个性化水印不得进入仓库。作者主动添加的公开署名水印不在此限。

私信、非公开帖子、IP 地址、密码、访问令牌、登录凭据、会话标识和其他未公开个人资料不得登记直链、上传附件或提交到 Git。发现这类内容时只记录需要重新制作素材，不保存原图。

## 本地文件

通过审核的展品素材放在 `exhibits/<id>/assets/`，并写入该展品的 `assets` 字段。博物馆共用的地板、家具、角色和音效放在根 `assets/`，登记到 `ASSETS.yml` 的 `assets`。

本地记录需要稳定 ID、文件路径、媒体类型、替代文本、原始来源、创作者、获取日期、SHA-256、隐私复核结果和权利依据。即使设置 `publish: false`，文件进入公开 Git 仓库后也已经发生再分发，因此本地文件只接受以下权利状态：

- `licensed`：许可证允许再分发，并填写许可证和所需署名。
- `permission_granted`：权利人明确授权，并填写 `docs/permissions/` 下的许可记录。
- `self_created`：贡献者原创，并同意按仓库说明发布。
- `generated`：由生成工具制作，来源、提示词和后续编辑过程可追溯。

`permission_required` 和 `unknown` 只能用于候选记录，不能对应仓库中的素材文件。代码采用 MIT、Apache-2.0 等许可证，也不自动表示应用名称、Logo、商标、商店图和截图都采用相同许可证。

## 从候选转为本地素材

1. 核实许可证，或取得权利人的明确许可。
2. 检查图片中的帖子、用户名、头像、水印和设备信息，完成必要裁切或脱敏。
3. 下载原文件，必要时制作 WebP、poster 等派生版本，并保留原始出处。
4. 把候选记录移动到展品或共享素材记录，沿用稳定 ID，补齐本地路径、媒体类型、替代文本和 SHA-256。
5. 运行 `pnpm check`。候选和本地素材不能同时使用同一个 ID。

## 授权记录

公开许可链接可以直接写入素材记录。私聊或邮件授权只在 [permissions/](permissions/) 中保存脱敏摘要，包括素材 ID、授权对象、范围、日期、是否允许修改和维护者确认。私人联系方式、完整聊天记录和原始私信保存在仓库之外。
